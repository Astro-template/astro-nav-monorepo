# astro-nav 代码评审要求

## 评审维度

在重构之前，需要对现有代码进行全面评审，确保重构方向正确。

### 1. TypeScript 规范

- 是否有 `any` 类型
- 接口/类型定义是否完整
- 是否使用了严格模式（strict: true）
- 泛型使用是否合理
- 导出是否清晰（named export vs default export）

### 2. 面向接口/面向对象

- 是否定义了 Protocol/Interface
- 类的职责是否单一
- 是否有 God Class（一个类干太多事）
- 依赖是否通过接口注入而非硬编码

### 3. 模块化

- 文件职责是否单一
- 是否有循环依赖
- 公共逻辑是否抽取到 shared 包
- 包之间的边界是否清晰

### 4. 日志规范

- 是否有结构化日志
- 错误处理是否有日志输出
- 是否有 console.log 残留（应该用统一的 logger）

### 5. Astro 最佳实践

- 是否正确使用 Content Collections
- 组件是否遵循 Islands 架构（最小化客户端 JS）
- 是否有不必要的客户端 hydration
- 静态数据是否在构建时获取（而非运行时）
- Props 接口是否定义

### 6. 代码组织

- 目录结构是否清晰
- 命名是否一致（文件名、变量名、函数名）
- 是否有死代码/未使用的导入
- 注释是否有价值（解释 why 而非 what）

### 7. 可维护性

- 硬编码值是否提取为常量/配置
- 重复代码是否抽取
- 错误处理是否完善
- 边界情况是否考虑

## 评审输出格式

按优先级列出问题，每个问题包含：
- 文件路径 + 行号
- 问题描述
- 建议修复方式
- 优先级（P0 必须修 / P1 建议修 / P2 可选）
